# Слой — лендинг графического дизайна

Полноценный локальный проект графического дизайна для Николая Парфенкова. «Слой» — предложенное рабочее имя, не подтверждённая регистрация бренда. Боевой сайт не опубликован.

## Запуск

Нужен Node.js 20+. В PowerShell из папки проекта:

```powershell
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173. Остановка — Ctrl+C. `npm run build` создаёт `dist/`, `npm start` запускает готовую сборку. Sharp нужен только для повторной оптимизации исходных изображений: `node scripts/images.mjs`. На клиенте нет фреймворка и внешних библиотек.

## Публикация на Netlify

В корне репозитория добавлен `netlify.toml`: Node.js 22, команда сборки `npm run build`, каталог публикации `dist`. При подключении репозитория выберите ветку `main` и корень проекта как базовый каталог. Netlify собирает страницы из исходников; загружать `dist/` в Git не требуется.

Этот вариант публикует интерфейс и статические страницы. Netlify не запускает `server.mjs`: для регистрации, входа и отправки заявок требуется отдельно развернуть Node-сервер с постоянным хранилищем и настроить маршрутизацию `/api/*` к нему. Пока сервер не подключён, публикация на Netlify подходит для просмотра дизайна, а не для приёма заказов и создания аккаунтов.

На статическом предпросмотре `/account` и `/account/` временно перенаправляются на форму `/sign-in/`, откуда доступна регистрация `/sign-up/`. После подключения API удалите два временных правила `[[redirects]]` из `netlify.toml`, чтобы открыть настоящий кабинет. Локальный Node-сервер продолжает обслуживать кабинет с авторизацией.

## Где редактировать

- `src/config.mjs` — бренд, домен, контакты, юридическое лицо, документы. Неподтверждённые значения оставлены `null`, без чужих реквизитов.
- `src/content.mjs` — все услуги, цены, состав тарифных направлений, проекты и FAQ.
- `src/project-stories.mjs` — пояснения к девяти примерам и точки увеличения деталей.
- `scripts/build.mjs` — HTML главной и дополнительных страниц.
- `src/homepage-sections.mjs` — галерея, каталог услуг, знакомство с координатором и открытые условия заказа. Тарифы «Базовый / Профессиональный / Премиум» убраны с главной, из навигации и из форм.
- `public/styles.css`, `public/app.js` — интерфейс и его поведение.
- `server.mjs` — обработка форм, серверная проверка, ограничение частоты и уведомления.
- `src/accounts.mjs` — собственные пользователи, хеши паролей, сессии и профиль.
- `src/account-pages.mjs`, `public/account.js` — страницы регистрации, входа и кабинета.
- `assets-original/` — оригиналы изображений портфолио, услуг и первого экрана; `public/assets/` — WebP в трёх размерах, OG и локальный шрифт Onest с лицензией.
- `docs/source-audit.md` — источники, фактология, отличия live/repo, нерешённые противоречия.
- `docs/verification.md` — результаты проверки и её границы.
- `docs/image-prompts.md` — точные запросы генерации изображений.

После изменений выполнить `npm run build` и обновить страницу. Сервер не делает hot reload; после изменений серверной конфигурации перезапустить его.

## Подключение заявок

Без настроек сервер возвращает **503**, сохраняет заполнение формы в открытой вкладке и не отправляет сведения внешним сервисам. Успех появляется только после HTTP 2xx и явного положительного подтверждения получателя. Таймер не имитирует доставку.

1. В `src/config.mjs` подтвердить бренд, домен, контакты и фактическое юридическое лицо. Положить утверждённые HTML-фрагменты четырёх документов в `legal/`, прописать пути в `site.documents` и установить `site.legal.ready=true`. Пока этого нет, страницы честно объясняют статус предпросмотра и не выдают текст за публичную оферту.
2. Скопировать `.env.example` в `.env`, выбрать `REQUEST_PROVIDER`. Ключи находятся только в серверной среде; `.env` исключён из Git.
3. `webhook`: задать HTTPS `REQUEST_WEBHOOK_URL`, при необходимости `REQUEST_WEBHOOK_TOKEN`. Получатель принимает JSON с `kind`, именем, email, идентификатором и названием услуги, сообщением, количеством, срочностью, размерами, цветами, референсами, согласием, UUID заявки и временем. Контракт ответа: `{ "ok": true }`, `{ "success": true }` либо `{ "status": "success" }`.
4. При размещении за HTTPS reverse proxy задать `PUBLIC_ORIGIN` точным origin нового сайта. `/api/requests` должен обслуживаться Node-сервером, а не статическим хостингом.
5. Пересобрать и выполнить одну согласованную сквозную проверку с владельцем получателя. Проверить появление заявки и выбранной услуги на стороне сервиса, отказ/таймаут, повторное нажатие.

Идемпотентность и rate limit находятся в памяти одного процесса (15 минут и 15 попыток/10 минут соответственно). Для нескольких реплик/длительных гарантий дедупликации получатель должен хранить `requestId`; при рестарте память процесса очищается.

## Кабинет, вход и регистрация

Сайт полностью независим от Sibax. Маршруты `/sign-up/`, `/sign-in/`, `/account/` обслуживаются этим проектом. Ни пароли, ни сессии не передаются другому сайту; внешнего перехода нет.

Регистрация: имя, email, телефон, компания, часовой пояс и два согласия; следующий шаг — самостоятельная установка пароля (10–128 символов). Это осознанное отличие от текста Sibax о пароле по почте: здесь создание аккаунта работает без чужого backend и без обещания отправить неподключённое письмо. После регистрации пользователь входит в свой кабинет. Вход — email и пароль; профиль редактируется, пароль меняется, выход отзывает сессию.

Хранилище по умолчанию `data/accounts.json`, можно изменить через `ACCOUNT_DATA_FILE`. Оно не попадает в Git или `dist/`. Пароли хешируются scrypt с индивидуальной солью; токены сессий хранятся как SHA-256. Cookie HttpOnly, SameSite=Lax, на 7 дней; Secure включается при HTTPS PUBLIC_ORIGIN. Смена пароля отзывает все прежние сессии. Сервер ограничивает частоту попыток, проверяет Origin, размеры и типы данных. Профили доступны только владельцам.

Файловое хранилище рассчитано на **один Node-процесс** с постоянным диском: изменения сериализуются, файл заменяется атомарно. Перед масштабированием нужна транзакционная БД и общее хранилище rate limit. Резервируйте файл и ограничьте доступ к нему учётной записью сервера. За reverse proxy выставьте PUBLIC_ORIGIN; лимит попыток сейчас использует адрес непосредственного соединения.

В текущем кабинете работают личные данные и пароль. Заказы, оплата, файлы, подтверждение email и восстановление пароля по почте не реализованы и не имитируются. Подключение коммерческих заявок описано выше; оно не требуется для работы регистрации и входа.

## Условия, требующие решения

На исходном сайте расходятся сроки и пороги авансовой оплаты. В delivery опубликованы 3 правки в 14 дней, экспресс +50%, архив 12 месяцев. Эти непротиворечивые опубликованные условия сохранены в конфигурации и FAQ, как требует бриф. Перед запуском устранить противоречия сроков и предоплаты и утвердить окончательные документы фактического исполнителя.

## Проверки

```powershell
npm run build
npm run check
npm test
```

`check` проверяет девять страниц, внутренние ссылки и якоря, изображения и srcset, ссылки ARIA и уникальность ID. 25 тестов покрывают собственные аккаунты и сессии, контракт заявок, валидацию, серверные ошибки, неподключённый получатель, параллельные повторы, независимый webhook, отмену анимаций, reduced motion и мобильный каталог, однократность появления при прокрутке и остановку движения при фокусе. Визуально проверены ширины от 320 до 1440 px, фильтры портфолио, просмотр деталей и переход к заказу.

## Перед публикацией

Нужны: подтверждённое название/домен; контакты нового сервиса; фактический исполнитель и оператор данных; четыре согласованных документа; единые условия заказа; получатель заявок и тестовый доступ; постоянное хранилище собственных аккаунтов и резервное копирование. До установки домена сборка закрыта от индексации. С доменом формируются canonical, абсолютный OG URL и sitemap. Публикация — только по отдельному поручению.

Для Node-хостинга: выполнить сборку, запустить `npm start` как сервис, проксировать HTTPS на `127.0.0.1:4173`. Для аккаунтов и форм нужен Node-сервер и постоянное хранилище: выкладывание одного `dist/` не подключит `/api/auth/*` и `/api/requests`.
