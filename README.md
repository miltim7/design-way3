# Слой — графический дизайн

Сайт графического дизайнера Николая Парфенкова: услуги, примеры оформления, анимационные ролики, формы заказа и личный кабинет.

Опубликованная версия: https://designway3.netlify.app/

## Технологии

HTML, CSS и JavaScript без клиентского фреймворка. Разметка собирается из JavaScript-шаблонов и данных в готовые HTML-страницы. Node.js обслуживает серверные API; статическая сборка находится в `dist/`.

## Локальный запуск

Нужен Node.js 20 или новее.

```powershell
npm ci
npm run dev
```

Адрес: http://127.0.0.1:4173/. Остановка — Ctrl+C.

`npm run build` обновляет `dist/`. `npm start` запускает сервер готовой сборки. После изменения серверного кода или конфигурации сервер нужно перезапустить.

## Каталог и портфолио

16 услуг и 29 проектов в двух подборках: «Работы Николая 10» открыта по умолчанию, «Примеры услуг 19» доступна отдельно. Десять проектов собраны из 25 предоставленных изображений; они имеют `kind: 'provided'`, что не означает подтверждённого коммерческого заказа. Сохранены все 19 демонстраций, включая шесть примеров пекарни, архитектурного бюро, упаковки чая, свадебного приглашения, джазовой афиши и карточек рюкзака. Для услуг без фиксированной начальной цены отображается «Стоимость по задаче».

На главной у каждой работы есть краткая задача. Страница `/portfolio/` показывает те же проекты с разбором задачи, решения и материалов. Пустые категории скрываются, при смене подборки категория сбрасывается; стрелки просмотра следуют текущему видимому набору. В проекте фестиваля 10 изображений, в журнале об образовании — семь: переключение через горизонтальные миниатюры со счётчиком. Страница `/about/` знакомит с дизайнером; настоящий предоставленный портрет также используется на главной. Обе страницы доступны из шапки, мобильного меню и футера. Состав сведений, перечень работ и порядок добавления материалов описаны в [docs/portfolio-content.md](docs/portfolio-content.md).

Ролики проигрываются без звука прямо в карточках при попадании в видимую область. Есть отдельная пауза; превью останавливаются вне экрана, в скрытой вкладке и при открытии диалога. При уменьшенном движении доступны постер и ручной запуск. Полный просмотр открывается по нажатию. Ролик о доставке не содержит аудиодорожки, музыкальный пример содержит оригинальную музыку. Фотографии товара сравниваются ползунком «до/после».

Готовые медиа входят в репозиторий. Для обычного запуска сайта повторная генерация не требуется. Изображения оптимизируются скриптами `scripts/images.mjs`, `scripts/expanded-assets.mjs` и `scripts/additional-portfolio-assets.mjs`. Последний создаёт три размера WebP для каждого из шести дополнительных примеров и сохраняет запросы генерации в соседних JSON. Инструкции и запросы: [дополнительные примеры](docs/additional-portfolio-assets.md), [расширенные медиа](docs/expanded-portfolio-assets.md), [основные изображения](docs/image-prompts.md).

Предоставленные изображения обрабатываются командой `node scripts/designer-assets.mjs`: 25 оригиналов и портрет из `assets-original/designer/` дают 78 WebP и 78 JSON с происхождением в `public/assets/designer/`. Варианты создаются без увеличения исходников и без изменения композиций. Манифест — `src/designer-assets.json`; исходный переданный архив и пять неотобранных изображений сохраняются отдельно без изменений. Подробности резервного копирования и воспроизведения — в документации материалов.

## Публикация

`netlify.toml` задаёт Node.js 22, команду `npm run build` и каталог публикации `dist`. Ветка публикации — `main`, базовый каталог — корень репозитория.

Netlify публикует статические страницы. Для работы серверных API нужно разместить `server.mjs` на Node-хостинге с постоянным диском и настроить маршрутизацию `/api/*`. При размещении всего проекта на Node-хостинге выполнить сборку, запустить `npm start` как сервис и проксировать HTTPS на порт 4173.

В `netlify.toml` заданы перенаправления `/account` и `/account/` на `/sign-in/`. Если хостинг не применяет эти правила, `public/account.js` открывает вход при недоступном API. После подключения API аккаунтов два правила следует удалить.

## Настройка API заявок

1. В `src/config.mjs` заполнить контакты, домен и реквизиты исполнителя, проверить документы из `site.documents` и установить `site.legal.ready=true`.
2. Создать `.env` по `.env.example`. Задать `REQUEST_PROVIDER=webhook`, HTTPS-адрес `REQUEST_WEBHOOK_URL` и при необходимости `REQUEST_WEBHOOK_TOKEN`.
3. Для HTTPS reverse proxy указать `PUBLIC_ORIGIN` — точный origin сайта.
4. Получатель webhook должен ответить HTTP 2xx и JSON с `ok: true`, `success: true` или `status: "success"`.

Заявка содержит выбранную услугу, имя, email, описание, параметры брифа, согласие и `requestId`. Успешная отправка отображается только после подтверждения API. При ошибке введённые данные остаются в форме. Повторная отправка с тем же `requestId` защищена от дублирования в пределах одного процесса. Идемпотентность и ограничение частоты хранятся в памяти; для нескольких реплик требуется общее хранилище.

Секреты должны находиться в серверной среде, не в `src/` или `public/`. `.env` исключён из Git.

## Аккаунты

Маршруты: `/sign-up/`, `/sign-in/`, `/account/`. Пользователь задаёт пароль при регистрации. Кабинет содержит личные данные, смену пароля и выход из аккаунта.

Хранилище — `data/accounts.json`; путь меняется через `ACCOUNT_DATA_FILE`. Файл исключён из Git и статической сборки. Пароли хешируются scrypt с индивидуальной солью, токены сессий — SHA-256. Cookie: HttpOnly, SameSite=Lax, срок 7 дней; Secure включается при HTTPS `PUBLIC_ORIGIN`. Смена пароля отзывает остальные сессии.

Файловое хранилище рассчитано на один Node-процесс с постоянным диском и резервным копированием. История заказов, платежи, файловый обмен, подтверждение email и восстановление пароля по почте — отдельные серверные интеграции.

## Проверки

```powershell
npm run build
npm run check
npm test
```

`check` проверяет одиннадцать HTML-страниц, ссылки, медиа, якоря, уникальность ID и ARIA-связи. Набор из 35 тестов покрывает аккаунты, сессии, заявки, анимации, каталог, HTTP-выдачу видео, видеопревью, подборки портфолио и загрузку дополнительных изображений. Локальные проверки от 27 октября 2026 года пройдены; обновление опубликованной версии проверяется после развёртывания.
